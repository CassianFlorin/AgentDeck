# Features

- **Sessions sidebar.** Every session keeps running in the background. Switch with `⌘⇧[` / `⌘⇧]`.
- **Agents.** Built-in presets for Claude Code, Codex, Grok and Gemini, plus your own (any CLI) in 管理 Agent. AgentDeck checks your login shell's PATH to show which are installed, and gives the install command for the rest. The agent command is typed into your login shell, so you drop back to a working shell when the agent exits.
- **Per-agent status.** The sidebar shows 运行中 / 等你 / 本轮完成 / 已退出 for each agent session. Claude Code reports exactly via its hooks: AgentDeck passes `--settings` at launch and never edits your settings files. Other agents are tracked from generic signals: Return pressed, bell and OSC 9/777 notifications (which also set a Dock badge), OSC 9;4 progress, and the agent exiting. `⌘⇧J` jumps to the next session that needs you. Each state has its own motion (a shimmer while working, a ripple while it waits for you, a bounce when a turn ends), all off under Reduce Motion.
- **Your Ghostty config just works.** AgentDeck loads `~/.config/ghostty/config`, so your fonts, themes and keybinds carry over.
- **IME support.** Chinese, Japanese and Korean input methods work, with the candidate window anchored at the cursor.
- **Splits.** `⌘D` / `⌘⇧D` split right/down; `⌘[` `⌘]` or `⌘⌥←↑↓→` move between panes; `⌘⌃←↑↓→` resize; `⌘⇧↩` zoom; `⌃⌘=` equalize. New panes inherit the current folder. Layouts are restored on relaunch.
- **Find & scrollback.** `⌘F` to find, `↩` / `⇧↩` (or `⌘G` / `⇧⌘G`) to step through matches, with a match counter. `⌘E` searches the current selection. An overlay scroll indicator can be dragged. `⌘↑` / `⌘↓` jump between prompts.
- **Paste images and files.** `⌘V` with a screenshot on the clipboard saves it as a PNG and pastes its path, which is how you hand an agent an image. Copied or dragged files paste as shell-escaped paths.
- **Rename & group sessions.** Right-click a session to rename it or move it into a group. Groups are collapsible sidebar sections. `⌘1`–`⌘9` jump to a session.
- **Remote servers (ECS / VPS / any SSH host).** The sidebar's 服务器 section lists saved servers plus every alias in `~/.ssh/config`, including `Include`d files, so hosts you already configured just work. Right-click an `~/.ssh/config` entry to remove it from the list; this only hides it in AgentDeck and never edits the file, and hidden entries can be restored. Add or edit a server with name, address, user, port, key / ssh-agent / password (stored in the Keychain), ProxyJump, login directory, TERM and extra ssh args. A live command preview and a "测试连接" button show the OS, whether tmux/zellij is installed, and existing sessions.
- **Nothing to install on the server.** By default (自动), AgentDeck uses tmux or zellij if the server happens to have one, and otherwise a plain login shell, with no warning. If a disconnect hits a session that runs in tmux/zellij, reconnecting re-attaches, so whatever was running, an agent included, is still there. Without a multiplexer, reconnecting simply logs in again, in the configured directory. Either way the session shows 已断开 with a reconnect button (`⌘⇧R`), and SSH sessions reconnect automatically on relaunch. You can also force tmux or zellij per server, or attach to an existing tmux/zellij session.
- **Ghostty's ssh integration works.** With `shell-integration-features = ssh-terminfo,ssh-env`, typing `ssh` in AgentDeck behaves like it does in Ghostty. AgentDeck bundles a `ghostty` entry point that runs Ghostty's CLI actions.
- **Resume conversations.** Each session remembers its agent conversation. Claude Code and Grok get an id from AgentDeck at launch; for Codex, AgentDeck finds the id in `~/.codex/sessions` after launch. Relaunching AgentDeck, or restarting an agent that exited, resumes the same conversation (`--resume <id>` / `codex resume <id>`). `⇧⌘O` 恢复之前的对话 lists an agent's past conversations for a folder, with titles, read from the agent's own session store.
- **Restore on relaunch.** Sessions, splits, groups and SSH connections come back as they were, as fresh processes. With nothing to restore, AgentDeck opens a shell in `~`.
- **Dark glass window.** AgentDeck is always dark. 设置 → 外观 (`⌘,`) sets the background opacity (30–100%) and blur; the terminal, title bar and sidebar share one translucent tint, while text stays opaque. This overrides `background-opacity` / `background-blur` from your Ghostty config inside AgentDeck only.
- **Visual Ghostty settings.** 设置 → 终端 picks a color theme (all of Ghostty's bundled themes plus your own, with swatches and search), font, size, line height, cursor style and blink, padding, Option-as-Alt, copy-on-select and hiding the mouse while typing, with a live preview. Every option starts as 跟随 Ghostty; changed ones are layered on top of your Ghostty config and applied to all terminals immediately. Your Ghostty config file is never modified, and a button opens it for anything not covered.
- **Performance monitors.** The gauge button in the toolbar (or 显示 → 显示性能监视器, `⌥⌘P`) opens a 性能 panel on the right. It follows the selected session: this Mac for local sessions, the server for SSH sessions. It has live charts for CPU (per core, plus load average on servers), memory, GPU (Apple GPU, or NVIDIA via `nvidia-smi` on servers), network, disk, and 会话占用 (each session's process tree on the Mac; the busiest processes on a server). Pick which monitors to show, and how often they refresh (1/2/5 s), from the panel's menu. A server is sampled through one ssh connection running a small POSIX-sh loop over `/proc`, so nothing is installed on it (Linux only). The panel is closed by default, and nothing is sampled, and no connection is kept, while it is closed or the window is hidden.
- **Docker.** The panel's Docker card lists the containers on this Mac or the server, with state, CPU and memory. From a container's menu you can open its logs (`docker logs -f`) or a shell inside it in a new session, start it, and stop or restart it (after a confirmation). Those sessions aren't restored on relaunch.
- **In-app updates.** AgentDeck checks for a new release once a day, and you can check any time with AgentDeck → 检查更新…. Updates come from GitHub Releases through [Sparkle](https://sparkle-project.org). Each one is EdDSA-signed and must carry the same Developer ID signature as the app you have. If an agent is mid-turn, AgentDeck asks before restarting, and you can let the update install when you quit instead.

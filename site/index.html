状态如何识别How status is detectedhooks、通用信号和几个例外hooks, generic signals, and a few exceptions
  • Claude Code 用它自己的 hooks 报告状态。AgentDeck 只在启动时加上参数，不改你的设置文件。Claude Code reports through its own hooks. AgentDeck passes flags at launch and never edits your settings files.
  • Grok 和 Codex 也能这样报告，在「管理 Agent」里打开就行。它们只从自己的配置目录读 hooks，所以会各新建一个 AgentDeck 自己的文件：~/.grok/hooks/agentdeck.json 和 ~/.codex/agentdeck.config.toml。你已有的配置不动，关掉开关就删除，在 AgentDeck 之外它们什么也不做。两个 Agent 都会先让你信任新 hook。Grok and Codex can report the same way once you turn it on in Manage Agents. They only read hooks from their own config folder, so each gets one new file of AgentDeck's own: ~/.grok/hooks/agentdeck.json and ~/.codex/agentdeck.config.toml. Your existing config is left as it is, turning the switch off deletes the file, and the hook does nothing outside AgentDeck. Both agents ask you to trust a new hook first.
  • 没有 hooks 的 Agent 靠通用信号判断：回车、响铃、通知和进度。Agents without hooks are read from generic signals: Return, the bell, notifications, and progress.
  • 刚启动、还在等第一次输入时，显示「就绪」。普通 Shell 没有这些状态。Right after launch, before the first prompt, the label is 就绪 (ready). A plain shell has none of these states.
  • 响铃和通知也会在 Dock 上标出来。SSH 断了以后提示为「已断开」，旁边有重连按钮，⌘⇧R 也会重连。Bells and notifications also badge the Dock. A dropped SSH session is marked 已断开 (disconnected) with a reconnect button; ⌘⇧R reconnects too.
  • 动效也有含义：运行中，文字上有一道光扫过；等你，圆点外面的圈会扩出去。系统打开「减弱动态效果」后，这些动画会停。The motion means something: while working, a light sweeps across the label; while waiting, a ring expands from the dot. With Reduce Motion on, the animation stops.

连接、回连和远程采样的条件Connecting, reattaching, and remote stats
  • 「服务器」里有你添加的主机，也有 ~/.ssh/config 里的别名，Include 进来的文件也算。可以填地址、用户、端口、密钥或 ssh-agent，也支持 ProxyJump。密码放在钥匙串里。Servers lists hosts you add and every alias in ~/.ssh/config, including files pulled in with Include.   • 默认是自动：机器上已经有 tmux 或 zellij 就用它，没有就开一个普通登录 shell，不会催你去装。Auto is the default: if the machine already has tmux or zellij, AgentDeck uses it. If not, you get a normal login shell, with no prompt to install anything.

对话是怎么对上的How conversations are matched
  • 回到同一段对话靠的是对话 id。Claude Code 和 Grok 在启动时就带上 AgentDeck 分配的 id。Codex 不能预先指定，要等它收到第一条提问、写出会话文件后，AgentDeck 才从 ~/.codex/sessions 里对上。Returning to the same conversation depends on a conversation id. Claude Code and Grok start with an id AgentDeck assigns. Codex cannot be given one up front: once it has received its first prompt and written its session file, AgentDeck matches the id from ~/.codex/sessions.
  • 没有 id 的时候（Gemini，或者还没提过问的 Codex）：重启 App 会接上这个文件夹里最近的一段对话；在 App 里重新启动一个已退出的 Agent，则是开一段新对话。Without an id (Gemini, or Codex before its first prompt): relaunching the app continues the most recent conversation in that folder, while restarting an exited agent inside the app starts a new conversation.
  • ⇧⌘O 按文件夹列出过去的对话，选一段恢复。支持 Claude Code、Codex 和 Grok。⇧⌘O lists past conversations for a folder, so you can resume one. It covers Claude Code, Codex, and Grok.
  • 自定义 Agent：「新对话参数」和「恢复对话参数」里都写了 {id}，AgentDeck 才会自己生成 id 并回到同一段对话。只填了「继续最近对话参数」的，重启 App 时接最近一段。两样都没填，每次都是新对话。Custom agents: AgentDeck generates an id and returns to the same conversation only when both the new-conversation and the resume arguments contain {id}. With only the continue-latest arguments filled in, relaunching the app continues the most recent conversation. With neither, every start is a new conversation.
  • 从 Docker 容器打开的会话，下次启动 App 时不会恢复。第一次打开、没有可恢复的内容时，会在家目录开一个 shell。Sessions opened from a Docker container are not restored on the next launch. With nothing to restore, AgentDeck opens a shell in your home directory.

You need macOS 14 or later, Xcode 16 or later, XcodeGen, and Zig (the version named by minimum_zig_version in vendor/ghostty/build.zig.zon).

Debug 配置是 ad-hoc 签名，不需要证书。Xcode 26 及以后，Metal 编译器是单独的组件，装一次就行：

The Debug configuration is ad-hoc signed, so no certificate is needed. On Xcode 26 and later the Metal compiler is a separate component; install it once:

xcodebuild -downloadComponent MetalToolchain

If Zig fails to fetch its dependencies (a 400 behind an HTTP proxy, or hash mismatch / DirNotEmpty), fetch them with curl first and build offline:

scripts/prefetch-zig-deps.sh
ZIG_SYSTEM_DIR=vendor/zig-deps/pkg scripts/build-ghosttykit.sh
